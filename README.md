# 台北公車 · iPhone

以地圖為主的台北公車 App，優先適配 iPhone 17。SwiftUI 介面、CoreLocation 定位、URLSession 資料更新，搭配 MapLibre Native 與 Metal，把簡單的灰色公車模型畫入地圖道路的 3D 場景。

底圖使用免金鑰的 OpenFreeMap，配色接近 Apple Maps；**目前不是 Apple Maps 底圖**。原生版直接連接臺北市公開 HTTPS 資料，使用時不需要電腦、Node 伺服器或 TDX 金鑰。

## 手機操作

- 開啟即看到地圖、站牌與近期回報的公車。沒有常駐資訊面板；資訊跟隨選中的站牌或車輛。
- 首頁主要入口是「你想去哪裡？」。使用 Apple MapKit 搜尋地點、地址或站名，從目前位置或手動出發地找附近可搭的上車站，以及目的地附近的下車站。開啟行程或點定位按鈕才請求使用期間定位權限。
- 提供直達與一次轉乘公車方案，按官方行駛版本與去返站序連接；不同支線不會拼成一段虛構路線。上、下車接駁先搜尋 800 m 內站牌，無方案才擴至 1,200 m；轉乘站牌最多相距 220 m。原生 Apple 步行路線再核對道路、距離與時間，過長接駁會提示改選。需要更多轉乘、捷運或服務範圍外的行程可直接交給 Apple 地圖。
- 選好目的地後，以半屏視窗同時顯示最多三個精簡公車方案，保留上方地圖；點整列即可選擇，不需先打開完整行程。取消或返回地圖會保留已選目的地與候車資訊。
- 選方案後返回候車地圖，重點顯示上車站、路線方向與官方下一班到站預估。完整地址與下車資訊收在可展開的細節。三輛同走法、同方向的公車依沿線距離排列，分別顯示位置推估時間；點車輛列即可追蹤、暫停或恢復跟車，只有所選車輛展開前方站牌。
- 「走到站牌」在同一張地圖顯示核對過的步行路線，保留到站時間及車輛資訊；完整行程仍可自行選擇 Apple 地圖步行導航。按「已上車」顯示下車站；「已下車」進入轉乘候車或最後步行。轉乘時顯示下一段的站牌、路線與車輛，誤按上車可返回等車，抵達後可結束行程。
- 官方到站時間沒有指定車牌。各車時間使用已收到的位置、近期移動及中間停靠站數估算為時間範圍，沒有把官方路線 ETA 指派給最近車牌。定位不可靠、已通過上車站或速度與近期移動皆不足時，不提供虛構時間。
- 首頁保留「站牌」「路線」快捷查詢。定位後提供兩個最近的實體站牌入口，點選時會重新移到該站並調整至街道尺度，不沿用先前拖曳或縮放的位置。定位按鈕先回到目前位置，再點可切換北朝上與手機方向；拖曳地圖或點羅盤會停止跟隨手機方向。
- 站牌搜尋預設以半屏清單搭配地圖，收藏與最近查看在前，地圖附近的站牌在後。移動地圖會更新附近清單，搜尋結果也能在地圖查看與點選；從詳情返回會保留查詢。
- 候車資訊與可互動地圖一起顯示；重新比較或取消路線選擇，仍保留目前跟蹤的車輛。拖曳地圖暫停跟車，點原車輛可恢復。資料更新不會把手動移動的地圖拉回。
- 地點搜尋接受常用捷運站名稱、台／臺、全形與英文站名，名稱匹配優先於距離；同名公車站牌先合併成可展開的一列，保留各實體站牌方向與地址。送出搜尋後自行選擇結果，不會直接採用第一個地點。沒有定位權限時，選好目的地後可手動搜尋出發地。
- 方案綜合步行、沿道路的車程、停靠站、候車和轉乘負擔排序；時間相近時優先少轉乘，明顯省時的轉乘仍可排前面，並保留一個直達備選。畫面上的「候車」是第一班車到上車站的官方預估，不是整趟時間。已知無法上車的路段會排除；普通導航不混入觀光巴士、懷恩專車，路線搜尋仍保留它們。
- 轉乘比較會先計算到達轉乘站的時間，已先開走的車不當成可銜接班次。缺少班距時採保守等待成本，已發布的首班時間可防止下午把夜間路線當成短時間可搭；即時到站資料優先於時刻範圍。這些是方案比較估計，並非承諾的全程抵達時間。Apple 步行路線補齊後會更新比較，乘客確認方案後則保留選擇。
- 點站牌查看官方路線到站時間，詳細頁可收藏站牌，或開啟 Apple Maps 步行導航。
- 路線搜尋提供數字、紅／藍／棕／綠／橘、小、幹線等專用按鍵，保留最近查看，可切換一般鍵盤搜尋路線或起訖站；「內科2」也可找到正式的「內科通勤專車2」。切換方向、點選公車即可追蹤，手動拖曳地圖會停止跟車。
- 路線清單完整使用官方 `GetRoute`，不限制前 60 條。2026-10-02 核對為 416 條主路線、722 個不重複行駛版本；數量隨官方資料更新。沒有近期 GPS 的路線仍保留，支援路線／英文代碼／別名／起訖站／支線搜尋與全形輸入。
- 主路線預設顯示全部走法的同方向車輛與各走法軌跡；詳情可用原生選單切換個別走法。單向走法自動選擇正確方向，車輛、站序及軌跡依版本篩選。全部走法的站牌列表顯示主要站序，分支站序在個別走法查看。
- 地圖上的路線方向可直接切換；站牌詳情可改看同名反方向站牌。收藏與最近查看的站牌優先出現在搜尋，目的地搜尋提供本機最近目的地。
- 車輛資訊包含車牌、路線方向、業者、低底盤資訊、GPS 回報速度與定位時間。
- 軌跡與站序能確認時，車旁顯示前方站牌及沿線距離，點一下即可查看該站官方預估；詳情提供前方三站。訊號暫缺、定位跳動和原始 GPS 分別標示。
- 點左上更新狀態可重試；詳情下拉更新會等待同一筆進行中的查詢。較舊來源資料不會覆蓋新資料。粗略定位顯示誤差範圍，過期使用者位置不再用來挑附近站牌。
- 開啟詳情時，地圖為車輛留出上方空間，避免被頁面遮住；缺少速度時顯示未提供，不當成停車。部分軌跡或站序失效時，站牌預估仍可使用，並在前景定期重試。
- 選車時淡化建築、強化灰色車身及藍色輪廓；可關閉凸顯，恢復正常建築遮擋。
- 搜尋、詳情與來源說明僅在需要時開啟原生 sheet，搜尋自動開啟鍵盤，支援 Dynamic Type、VoiceOver 與觸覺回饋。iOS 26 的浮動控制使用系統 Liquid Glass；減少透明度時使用實色。

## 定位、搜尋與快速更新

定位先採用系統或手機裡近期可用的位置，再持續改善精度；模糊位置可以先定位地圖，過舊或不夠精準的位置不作為自動規劃出發地。離開 App 停止定位，回到前景立即恢復。鏡頭不等待底圖及公車圖層下載，手動拖曳後不被新的定位拉回。

站牌搜尋在背景執行，先做名稱、別名及地址比對，沒有相符結果時才做錯字比對。地點搜尋合併連續輸入、取消過時查詢、短暫快取結果，支援英文站名與「我要去」等說法。正式名稱與站牌方向保留。

0.4.2 起支援現有文字、搜尋別名、外觀與方案偏好的內容更新。[內容更新手冊](ios/LIVE_UPDATES.md)列出已接上的欄位、發布及回復方式。連線或驗證失敗保留最後可用設定；定位與搜尋文字不送往設定端點。

官方剩餘秒數依來源時間倒數，使用完整分鐘顯示，避免「2 分 1 秒」直接變成「3 分」。到站與定位資料各自收到後立即顯示，不等待較慢的另一份資料。數字降至零代表接近到站，來源過期仍隱藏，不據此認定公車已到或把官方時間綁到車牌。

## 即時資料的意義

App 在前景每 15 秒查詢公車與到站資料；這不代表每輛公車的 GPS 都每 15 秒更新。定位超過 2 分鐘會顯示延遲、停止動畫。取得失敗保留最後資料的原始時間；到站預估過期或取得失敗時不顯示舊預估。背景暫停查詢和繪圖，返回 App 立即更新。公車來源由臺北市持續更新，不依賴觀看者開啟 App。

官方 `EstimateTime` 只提供路線／站牌預估，**沒有車牌綁定**。站牌的同方向車輛依路線、近期 GPS 及支線停靠站資料篩選。能確認行程進度時，按沿線距離排序並排除已通過車輛；否則標示 GPS 直線距離。訊號不確定的車輛不納入。車牌與路線 ETA 分開呈現，不能把最近車牌直接視為下一班。

GPS 在官方路線軌跡 40 公尺內時匹配軌跡；候選路段同時檢查前一個定位、可行移動距離、朝向與支線站序，減少平行道路、交叉路段與折返誤配。站牌投影使用順序動態規劃，預先快取可確認的去返行程。停車時 9 公尺內的抖動保留站定位置，但更新真正回報時間。超出合理位移的定位先等待第二筆連續回報確認；重新取得位置時直接恢復，不讓公車穿越未知街區。較舊的個別車輛回報不會倒退車輛資訊。

短暫缺少某車時，最多保留至最後定位的 90 秒並顯示訊號暫缺，維持原始時間；明確結束營運的車立即移除。相鄰回報屬於同車、同路線、同方向且間距合理，才沿路線轉彎平滑移動；無匹配時顯示原始 GPS，不推算尚未收到的未來位置。不提供車道級或高架高度定位。前方站牌與沿線距離是 GPS／路線推估，不是該車專屬到站預測。

## 原生地圖與效能

`ios/TaipeiBus/NativeBusLayer.swift` 是 MapLibre Native 的 Metal custom style layer。約 2.55 × 11.8 × 3.5 公尺的公車網格共用地圖相機與 3D depth buffer，遵循地圖透視與建築遮擋。凸顯模式讓選中的車輛略過遮擋，保持原本世界座標。車輛以 instancing 繪製，每幀最多 240 輛可見車；使用三組 GPU instance buffer 避免改寫仍在使用的資料。

灰色車身帶倒角、柔和方向光及邊緣光、窗帶、車頂設備與圓形車輪；貼地陰影由同一 Metal 場景繪製。輪圈依已知道路上的行進距離轉動。新 GPS 接續目前呈現的位置、朝向與車輪相位，保留尚未走完的路口；車身朝向平滑轉彎，停靠時緩停。所有位置仍限制在已收到的路徑，沒有未來位置預測。

跟車相機逐幀平滑追蹤，保留使用者的地圖朝向；選車的輪廓及建築透明度漸變。動畫向系統請求裝置最高更新率，iPhone 17 以 120 Hz 為目標；低耗電、較高溫或減少動態效果時降為 30 Hz。沒有移動或選取過渡時不要求連續重畫，背景暫停。實際 GPU、耗電與流暢度仍需在 iPhone 17 實機測量。

使用 [Apple Liquid Glass API](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views) 與 [CADisplayLink 更新率控制](https://developer.apple.com/documentation/quartzcore/cadisplaylink/preferredframeraterange)，系統決定實際更新率。

## 建置

最低 iOS 17；iPhone 17 模擬器使用 Xcode 26。在 Mac 開啟 `ios/TaipeiBus.xcodeproj`，選 TaipeiBus scheme 與 iPhone 模擬器，即可編譯。安裝到實機需自己的 Bundle ID 與 Apple Signing Team。

Windows 使用本專案的 GitHub Actions：`main` 提交或拉取請求中的 `ios/` 變更會執行 Swift 核心與發布腳本測試，編譯模擬器及 iPhone Release App。修改分支的普通提交不另外啟動重複的 macOS 工作；尚未建立拉取請求時，可手動執行 `iPhone app` 驗證。需要新原生截圖時，勾選 `capture_preview`，才啟動 iPhone 17、打包模擬器 App、保存功能截圖及嘗試有效的跟車影片；一般檢查只保存紀錄。車輛和 ETA 使用公開即時資料；附近站牌截圖的使用者位置由模擬器設定，候車介面驗證的三輛車則明確標示為測試資料。artifact 的 `.app` 僅供 macOS 模擬器，不能直接安裝到 iPhone。

[雲端建置及 TestFlight 步驟](ios/CLOUD_BUILD.md)提供完整帳號需求、Windows 設定腳本、App 記錄建立、內部安裝及外部測試步驟。獨立的 `TestFlight` workflow 自動簽名、上傳、核對指定版本並加入內部群組，Apple 處理延遲時可接續而不重傳；發布不等待模擬器截圖。簽名金鑰放在 GitHub Actions secrets，不寫入原始碼或聊天。

## 資料與授權

使用[臺北市公共運輸處公開 API](https://pto.gov.taipei/News_Content.aspx?n=A1DF07A86105B6BB&s=55E8ADD164E4F579&sms=2479B630A6BD8079)：`GetBusData`、`GetEstimateTime`、`GetRoute`、`GetStop`、`GetPathDetail`、`GetProvider`、`GetBusShape`。全部為公開 gzip JSON，來源為 `https://tcgbusfs.blob.core.windows.net/blobbus/`。

車輛與站牌範圍限制台北市區周邊（121.35–121.72°E、24.94–25.23°N），涵蓋目前官方路線的全部站牌，包含經過此範圍的跨市路線。底圖為 OpenStreetMap／OpenMapTiles、OpenFreeMap；地圖保留來源 attribution。MapLibre Native 固定為 6.31.0。SDK 及修改後 Liberty 樣式授權收錄於 `ios/TaipeiBus/Licenses.txt`。

## 本機驗證與手機預覽

0.4.4 的[原生操作驗證](https://github.com/rio10255254/TaipeiBus/actions/runs/37111958479)通過十項操作測試，涵蓋最近站牌的重新定位、手機方向／北朝上及羅盤、站牌地圖點選與返回、路線專用按鍵與搜尋紀錄、完整行程、上下車與轉乘，以及關閉定位後選出發地。亦確認新圖標在 iPhone 桌面顯示與點按啟動。方位使用受控模擬輸入；未據此宣稱已完成實機指南針或道路實測。手動驗證可選 `usability_scope=map-controls` 聚焦地圖與搜尋，或選 `routing-only` 只執行核心及官方資料核對。截圖預覽只包含手動命名的畫面及失敗證據，完整診斷另存。

0.4.3 的[原生操作驗證](https://github.com/rio10255254/TaipeiBus/actions/runs/37099237594)完成五項 iPhone 17 操作測試及實際截圖檢視：真實目的地搜尋、三個方案同屏、同地圖步行、追蹤與地圖拖曳、返回後保留車輛、上下車、轉乘、抵達、大字體，以及拒絕定位後手動選出發地。候車與轉乘車輛使用明確標示的固定測試資料，搜尋及路線使用官方服務；未以此宣稱已完成道路實測。手動預覽選 `preview_scope=usability` 可重現，截圖另存為 `usability-screenshots`。

`ios/TransitCore` 是可獨立測試的 Swift package。78 項離線核心測試涵蓋台北時區、異常及過期回報、同名站牌方向、支線停靠站、轉彎及反向路徑、重複 snapshot、ETA 與車牌分離，以及 GPS 動畫接續、剩餘路口、朝向跨北方、停車、舊回報、平行道路與重複交叉、缺少朝向／速度、GPS 抖動、異常位移確認、短暫漏報、結束營運、去返行程、已通過車輛、軌跡來源失效及資料不足時降級。新增完整路線清單、全形與英文代碼搜尋、支線篩選、單向站序、去返軌跡分開保留與匹配、地圖支線軌跡、手機半屏路線鏡頭及跨市站牌範圍的回歸測試。新增目的地規劃的正確方向、支線分離、真實轉乘、相鄰站牌、最近可搭站牌、缺少軌跡與穩定方案測試。手動擷取 iPhone 預覽時，另以當天官方資料核對全部路線與行駛版本 ID，並核對多個目的地的每段真實站序與轉乘接點。gzip 解壓縮已測試正常資料、截斷資料與大小限制。UIKit／Metal App 的編譯、截圖與影片由 macOS Actions 驗證；實機簽名另行處理。

原有 `src/`、`server/` 保留為手機尺寸的互動預覽，可在 Windows 查看設計：

```sh
npm install
npm run build
npm start
```

開啟 `http://localhost:4173/`。手機預覽已用 iPhone 17 的 402 × 874 pt 尺寸驗證站牌、路線、車牌、跟車與定位流程；瀏覽器畫面不代表原生 iOS 的實機驗證。`work/` 包含可重建的本機測試資料，不提交到 GitHub。
