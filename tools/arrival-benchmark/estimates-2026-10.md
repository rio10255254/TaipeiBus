# 站牌倒數接上官方到站預估（2026-10）

統一模型（`TravelTimeModel`）的第 3 層是官方到站預估：兩站預估的差就是那一段的車程。行程規劃與坐車時間早就用它，站牌倒數卻沒有接上。新北沒有官方站間車程，站牌倒數只能靠「這輛車近期的行駛」，所以比台北差（第一份雙北錄製：新北 2.1 分、台北 1.6 分），而同一批新北官方預估在 2–10 分反而比 App 準（1.1–1.5 分 對 1.6–1.8 分）。

現在 `VehicleArrivalForecast.ingest` 隨定位一起收下官方預估，沒有官方分時段車程、也沒有其他車剛通過紀錄的路段：

- 車所在的那一段：下一站自己的預估就是這輛車的時間（`TravelTimeModel.estimatedRemaining`）；同一段前面還有別輛車時不用，因為那是前車的；
- 之後各段：相鄰兩站預估的差（`TravelTimeModel.estimated`），中間已有車時不用。

依據標為「依官方到站預估的站間差距估算」。預估是狀態碼、超過兩分鐘沒更新或不合理時，自動退回原本的車速推估。

## 結果

同一批預估，逐筆比較改前改後（車在 30 分鐘內確實到站、不在站牌附近）：

| | 新北（10/30 晚） | 台北（10/30 晚） | 台北（4 份錄製） |
|---|---|---|---|
| 顯示分鐘的比例 | 29.9% → 33.6% | 84.8% → 85.2% | 73.2% → 74.2% |
| 有顯示的平均誤差 | 2.11 → 1.99 分 | 1.611 → 1.609 分 | 1.545 → 1.538 分 |
| 顯示時間有變的那些 | 2.85 → 2.45 分（4.9 萬筆） | 2.84 → 2.50 分（5,725 筆） | 2.19 → 1.91 分（2 萬筆） |
| 新增顯示的那些 | 1.83 分（3.9 萬筆） | 1.74 分（5,454 筆） | 1.51 分（1.4 萬筆） |
| 不再顯示的那些（原本的誤差） | 3.90 分（3,817 筆） | 3.55 分（287 筆） | 2.82 分（1,198 筆） |
| 落在參考範圍 | 73.9% → 73.4% | 84.5% → 84.4% | 84.6% → 84.4% |

這份新北錄製的官方預估是依站抽樣（20% 站牌），只有相鄰兩站剛好都抽到的路段量得到這一層，所以新北的改善被低估。10/31 起新北改依路線抽樣（`collect.py --sample route`），之後的錄製可以完整量測。
